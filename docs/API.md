# StockLens REST API

Screening data for a fixed universe of U.S. large-cap companies. Read-only:
every endpoint is a `GET`, there is no authentication, and no state is
changed by any request.

- **Base URL (local):** `http://localhost:8080`
- **Content type:** `application/json`
- **Errors:** [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) problem details
- **Machine-readable spec:** [`openapi.yaml`](openapi.yaml) — generated from
  the code; refresh with `cd backend && ./gradlew exportOpenApiSpec`

## Interactive documentation

With the backend running, the API documents itself:

| URL | What |
| --- | --- |
| <http://localhost:8080/swagger-ui.html> | **Swagger UI** — browse the endpoints and call them from the browser |
| <http://localhost:8080/v3/api-docs> | OpenAPI 3.1 spec, JSON |
| <http://localhost:8080/v3/api-docs.yaml> | OpenAPI 3.1 spec, YAML |

Generated by [springdoc-openapi](https://springdoc.org) from the controller,
so the spec cannot drift from the implementation. Descriptions come from the
Javadoc on `StockController` and `Stock` via therapi, so there is one place to
edit a description rather than a comment and an annotation that disagree.

This page stays hand-written because it carries the things a generated spec
does not: the reasoning behind the filter semantics, the degradation
behaviour, and the quota constraint.

> **Deployment note:** Swagger UI is a live request console against whatever
> instance serves it. Set `springdoc.api-docs.enabled: false` and
> `springdoc.swagger-ui.enabled: false` for a public deployment.

## Quick start

```bash
cd backend
export FINNHUB_API_KEY=your_key_here
./gradlew bootRun
```

```bash
# the whole universe, largest companies first
curl http://localhost:8080/api/stocks

# "large caps trading under 30x earnings, cheapest first"
curl "http://localhost:8080/api/stocks?maxPe=30&minMarketCap=500&sortBy=pe&order=asc"

# one company
curl http://localhost:8080/api/stocks/MSFT
```

Without an API key the app still starts and answers `503` with an explanation,
so you can exercise the error path without registering.

## `GET /api/stocks`

Screens the universe: free-text search, then filters, then sort.

**Query parameters** — all optional.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `q` | `string` | — | Case-insensitive substring matched against **ticker and company name**. Blank or omitted returns everything. |
| `maxPe` | `number` | — | Upper P/E bound, **inclusive**. Must be `> 0`. |
| `minMarketCap` | `number` | — | Lower market-cap bound in **billions** of USD — `500` means $500B. Must be `>= 0`. |
| `sortBy` | `string` | `marketCap` | One of `marketCap`, `pe`, `price`, `name`. |
| `order` | `string` | `desc` | `asc` or `desc`. |

**Returns:** `200 OK` with a JSON array of [Stock](#the-stock-object). An empty
result is `200` with `[]` — never `404`.

**Example**

```bash
curl "http://localhost:8080/api/stocks?q=micro&sortBy=pe&order=asc"
```

```json
[
  {
    "ticker": "MSFT",
    "name": "Microsoft Corp",
    "sector": "Technology",
    "price": 512.3,
    "peRatio": 29.5,
    "marketCap": 3.1E12,
    "dividendYield": 0.71,
    "lastUpdated": "2026-08-17T12:00:00Z"
  }
]
```

### Filter semantics

These three rules are the ones that surprise people, so they are pinned by
tests in `StockServiceTest.Filtering`:

- **`maxPe` is inclusive.** A P/E of exactly `29.5` passes `maxPe=29.5`.
- **A missing metric excludes the company.** If `peRatio` is `null`, the stock
  is dropped by any `maxPe` filter. "Unknown P/E" is not treated as "cheap".
  The same holds for `marketCap` and `minMarketCap`.
- **A negative P/E is kept.** A loss-making company reporting `-8.2` is
  genuinely below any positive ceiling, so `maxPe=30` returns it.

### Sort semantics

- Companies **missing the sorted metric are placed last in both directions** —
  reversing the order does not float `null`s to the top.
- Ties break on ticker, so the ordering is total and repeatable across calls.
- `sortBy=name` is case-insensitive (`Alphabet`, `Apple`, `Microsoft`).

## `GET /api/stocks/{ticker}`

Detail for one company **from the screened universe**.

| Path parameter | Type | Description |
| --- | --- | --- |
| `ticker` | `string` | Exchange symbol, matched case-insensitively. Must match `[A-Za-z][A-Za-z0-9.\-]{0,9}`. |

**Returns:** `200 OK` with a single [Stock](#the-stock-object).

```bash
curl http://localhost:8080/api/stocks/msft
```

```json
{
  "ticker": "MSFT",
  "name": "Microsoft Corp",
  "sector": "Technology",
  "price": 512.3,
  "peRatio": 29.5,
  "marketCap": 3.1E12,
  "dividendYield": 0.71,
  "lastUpdated": "2026-08-17T12:00:00Z"
}
```

> **Scope:** this searches the configured universe, not all of Finnhub. A real
> symbol that is not in `stocklens.screener.tickers` returns `404`, because the
> screener holds no snapshot for it.

## The Stock object

| Field | Type | Nullable | Description |
| --- | --- | --- | --- |
| `ticker` | `string` | no | Exchange symbol, e.g. `"MSFT"`. |
| `name` | `string` | no | Company name as reported by the provider. |
| `sector` | `string` | **yes** | Industry classification, e.g. `"Technology"`. |
| `price` | `number` | **yes** | Last trade price in USD. |
| `peRatio` | `number` | **yes** | Trailing P/E. `null` when undefined; negative for a loss-making company. |
| `marketCap` | `number` | **yes** | Market capitalization in **plain USD** (`3.1E12`), not millions. |
| `dividendYield` | `number` | **yes** | Trailing yield as a percentage — `0.71` means 0.71%. |
| `lastUpdated` | `string` | no | ISO-8601 instant the data was fetched, e.g. `"2026-08-17T12:00:00Z"`. |

**Every metric field can be `null`.** The provider does not guarantee each
metric for each company: a firm without positive earnings has no P/E, and one
that pays no dividend has no yield. Clients must handle `null` rather than
assume a number.

## Errors

All failures return an RFC 9457 problem detail:

```json
{
  "type": "about:blank",
  "title": "Not Found",
  "status": 404,
  "detail": "No stock found for ticker 'ZZZZ'"
}
```

| Status | When | Example `detail` |
| --- | --- | --- |
| `400` | Unknown `sortBy` or `order` | `Unknown sortBy 'volume'; expected one of: name, price, pe, marketCap` |
| `400` | Non-numeric filter value | `Parameter 'maxPe' has an invalid value` |
| `400` | `maxPe <= 0` or `minMarketCap < 0` | `Invalid request parameter: ...` |
| `400` | Malformed ticker in the path | `Invalid request parameter: ...` |
| `404` | Ticker absent from the universe | `No stock found for ticker 'ZZZZ'` |
| `503` | No cached data **and** the provider is failing | `Stock data is currently unavailable: the provider rate limit is exhausted` |

### About `503`

`503` is rarer than it looks, because the service degrades before it fails:

1. One ticker fails → skipped, the rest of the universe is still returned.
2. The whole refresh fails but a previous snapshot exists → **the stale
   snapshot is served**, with a `200`. Check `lastUpdated` if freshness matters.
3. The refresh fails and the cache is **cold** → `503`.

So a `503` means the backend has never successfully fetched data, or the
process restarted before it could. It is transient — retry.

## Configuration

Set in [`backend/src/main/resources/application.yml`](../backend/src/main/resources/application.yml),
overridable per environment.

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `stocklens.finnhub.api-key` | `string` | `${FINNHUB_API_KEY:}` | Finnhub token. Blank makes every fetch fail fast with a clear message. |
| `stocklens.finnhub.base-url` | `string` | `https://finnhub.io/api/v1` | API root. Pointed at a mock server in tests. |
| `stocklens.finnhub.connect-timeout` | `duration` | `3s` | TCP connect timeout. |
| `stocklens.finnhub.read-timeout` | `duration` | `5s` | Response read timeout. |
| `stocklens.screener.cache-ttl` | `duration` | `10m` | How long a snapshot is served before refreshing. |
| `stocklens.screener.tickers` | `list` | 18 symbols | The screened universe. |

Override the same values from the environment (Spring relaxed binding):

```bash
export FINNHUB_API_KEY=abc123
export STOCKLENS_SCREENER_CACHETTL=30m
```

> **Quota:** one refresh costs `3 × tickers.size()` calls and Finnhub's free
> tier allows 60/minute. The default 18 tickers cost 54. **Adding more than 20
> tickers will exceed the limit** and trigger rate-limited refreshes.

## Notes for client authors

- **Caching is server-side.** Responses carry no cache headers; the backend
  serves from a 10-minute in-memory snapshot. Polling faster than the TTL
  returns identical data without touching Finnhub.
- **`lastUpdated` is the freshness signal.** Under a provider outage the API
  keeps answering `200` with stale data, so surface this timestamp rather than
  assuming every `200` is current.
- **No pagination.** The universe is ~18 companies and the full array is
  returned. If the universe grows substantially, pagination becomes a breaking
  change worth versioning.
- **The API key never reaches the browser.** The frontend calls this backend
  only; Finnhub credentials stay server-side.
